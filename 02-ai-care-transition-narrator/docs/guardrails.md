# Guardrails & Safety Framework

## Why Guardrails Are Critical

LLMs can hallucinate — in healthcare, a hallucinated medication or missed allergy can cause patient harm. This document defines our safety architecture.

---

## Layer 1: Input Validation (Before AI Generation)

| Check | Implementation | What It Catches |
|-------|---------------|-----------------|
| **Patient exists** | Verify PATIENT_ID in cohort table before generating | Prevents orphan document generation |
| **Has conditions** | Require active_conditions IS NOT NULL | No narrative for patients without diagnosis data |
| **Has medications** | Flag if active_medications is NULL | Ensures med reconciliation has data to work with |
| **Allergy cross-check** | Pre-check: do any meds conflict with known allergies? | Catches conflicts BEFORE AI even runs |
| **Data recency** | Reject profiles older than 30 days | Prevents stale data from being narrated |

### SQL Implementation:
```sql
-- Pre-generation validation function
CREATE OR REPLACE FUNCTION SNF_AI_HUB.GOLD.validate_for_generation(transition_id INT)
RETURNS VARIANT
AS $$
    SELECT OBJECT_CONSTRUCT(
        'is_valid', CASE 
            WHEN active_conditions IS NULL THEN FALSE
            WHEN DATEDIFF(day, discharge_date, CURRENT_DATE()) > 30 THEN FALSE
            ELSE TRUE
        END,
        'warnings', ARRAY_CONSTRUCT_COMPACT(
            IFF(active_medications IS NULL, 'NO_MEDICATIONS', NULL),
            IFF(allergies IS NULL, 'NO_ALLERGIES_DOCUMENTED', NULL),
            IFF(DATEDIFF(day, discharge_date, CURRENT_DATE()) > 14, 'STALE_DATA', NULL)
        )
    )
    FROM SNF_AI_HUB.GOLD.transition_patient_profiles
    WHERE transition_id = transition_id
$$;
```

## Layer 2: Prompt Engineering Guardrails

### Rule: Only Report What's In The Data
Every prompt includes:
```
CRITICAL RULES:
- Only mention conditions explicitly listed in the patient data
- Only list medications from the provided medication list
- If information is missing, state "Not documented" — do NOT infer
- Never recommend a specific medication by name (only suggest "consult pharmacy")
- Flag any potential allergy-medication conflict with ⚠️ WARNING
```

### Rule: Structured Output Enforcement
```
Respond ONLY in the following format:
1. CLINICAL SUMMARY: [2 sentences max]
2. ACTIVE DIAGNOSES: [bullet list from provided conditions ONLY]
3. MEDICATIONS: [list ONLY from provided medications]
4. PRECAUTIONS: [based on conditions, NOT hallucinated]
5. FOLLOW-UP: [generic categories, NOT specific provider names]
```

### Rule: Explicit Limitations Disclosure
Every generated document includes footer:
```
---
⚠️ AI-GENERATED DOCUMENT — REQUIRES CLINICAL REVIEW BEFORE USE
Generated by: Snowflake Cortex AI (llama3.1-8b)
Data source: Patient clinical records as of [date]
This document has NOT been reviewed by a licensed clinician.
Do NOT use for clinical decision-making without physician approval.
```

## Layer 3: Output Validation (After AI Generation)

| Check | How | Action If Failed |
|-------|-----|-----------------|
| **Medication hallucination** | Compare mentioned meds against actual med list | Flag as INVALID, require human review |
| **Condition hallucination** | Compare mentioned conditions against condition list | Flag as INVALID |
| **Dangerous recommendations** | Check for phrases like "stop taking", "increase dose", "start [drug name]" | Block output, flag for pharmacist review |
| **Completeness** | All 5 sections present? Allergy section not empty when allergies exist? | Mark as INCOMPLETE |
| **Length check** | Clinical handoff < 2000 words, Family summary < 500 words | Truncate or regenerate |
| **Confidence markers** | If AI says "I'm not sure" or "might" — flag uncertainty | Route to physician review |

### SQL Implementation:
```sql
-- Post-generation validation
CREATE OR REPLACE TABLE SNF_AI_HUB.GOLD.narrative_quality_checks AS
SELECT
    transition_id,
    -- Check: Does handoff mention any medication NOT in the patient's med list?
    CASE WHEN clinical_handoff ILIKE '%aspirin%' 
         AND active_medications::VARCHAR NOT ILIKE '%aspirin%'
    THEN 'HALLUCINATED_MED' ELSE 'PASS' END AS med_hallucination_check,
    -- Check: Contains dangerous directive language?
    CASE WHEN clinical_handoff ILIKE '%stop taking%' 
         OR clinical_handoff ILIKE '%discontinue%immediately%'
         OR clinical_handoff ILIKE '%increase%dose%'
    THEN 'DANGEROUS_LANGUAGE' ELSE 'PASS' END AS safety_language_check,
    -- Check: Completeness (has all sections)
    CASE WHEN clinical_handoff NOT ILIKE '%diagnos%' 
         OR clinical_handoff NOT ILIKE '%medication%'
    THEN 'INCOMPLETE' ELSE 'PASS' END AS completeness_check
FROM SNF_AI_HUB.GOLD.transition_narratives tn
JOIN SNF_AI_HUB.GOLD.transition_patient_profiles tp ON tn.transition_id = tp.transition_id;
```

## Layer 4: Human-in-the-Loop (See approval_workflow.md)

No AI-generated document is used clinically until:
1. Generated → status = `DRAFT`
2. Reviewed by clinician → status = `REVIEWED`
3. Approved (with optional edits) → status = `APPROVED`
4. Only APPROVED documents are visible to patients/families

---

## Layer 5: Continuous Monitoring

| Metric | Target | Alert Threshold |
|--------|--------|-----------------|
| Hallucination rate (spot-check audits) | < 2% | > 5% → pause generation |
| Clinician edit rate (how often they modify AI output) | < 30% | > 50% → retune prompts |
| Average approval time | < 4 hours | > 24 hours → staffing issue |
| Patient satisfaction (if surveyed) | > 4.0/5.0 | < 3.5 → review family summaries |
| Readmission rate (with vs without narrative) | Measurable reduction | No improvement after 90 days → reassess |
